Why is i repeated? (4, 13, 40, …)

      
Every step must rotate by ±θᵢ = ±atanh(2⁻ⁱ). There is no "skip" (d is never 0). So if a step overshoots, all the later steps together must be able to rotate back:

      
θᵢ  ≤  θᵢ₊₁ + θᵢ₊₂ + θᵢ₊₃ + …       (each angle ≤ sum of all remaining angles)

      
    
        
  • Circular CORDIC: atan(2⁻ⁱ) = 2⁻ⁱ − 2⁻³ⁱ/3 + … is slightly less than 2⁻ⁱ, so the rule holds and no repeats are needed.
    • 
        
  • Hyperbolic CORDIC: atanh(2⁻ⁱ) = 2⁻ⁱ + 2⁻³ⁱ/3 + … is slightly more than 2⁻ⁱ, but the remaining sum is only ≈ 2⁻ⁱ. The rule fails: there is a gap of angles that can never be recovered.
    •

  • Example t = 0.55, no repeats: step 1 subtracts 0.5493 → z = 0.0007 (≥ 0), so step 2 is forced to subtract 0.2554 → z = −0.2547. All later steps together add back only 0.2507, so z gets stuck near −0.004 (~8 correct bits instead of ~16). Only some inputs fail, so this is a hard-to-find bug in hardware.
    • 
        
  • The fix: doing shift 4 twice adds one extra θ₄ ≈ 0.0626 to the "remaining" sum of every earlier step. That covers the gaps of i = 1, 2, 3 (0.043 + 0.0047 + 0.0006) and extends the range from 1.055 to 1.118.
    • 
        
  • Why 4, 13, 40 (kₙ₊₁ = 3kₙ + 1): the gap at step i is ≈ 2⁻³ⁱ. After repeating k, the biggest gap left (at step k) is ≈ 2⁻³ᵏ. It only matters once you want precision finer than that, i.e. N > ~3k, so the next repeat goes at 3k+1. Repeat 4 → fine up to ~12 iterations; also 13 → up to ~39; also 40 → beyond.
    • 
        
  • In hardware it's a constant, fixed at design time by N, never decided at run time (only d is). Index the atanh LUT by stage k, so a repeated value is simply stored twice. For N ≤ 39: shift(k) = k + 1 − (k ≥ 4) − (k ≥ 14). Unrolled design: one extra pipeline stage. Iterative design: the counter→shift mapping holds the same shift for one extra clock. Remember to include repeats in N and in K.
    • 
        
  • In this simulator, repeated shifts are the orange i in the iteration table.

How it works

      
Iteration k (k = 0, 1, …, N−1) takes the registers from xk, yk, zk to xk+1, yk+1, zk+1, using shift ik (from the schedule 1, 2, 3, 4, 4, 5, …) and direction dk = ±1:

      
xk+1 = xk + dk·(yk >>> ik)
yk+1 = yk + dk·(xk >>> ik)          ← note: PLUS (circular CORDIC has minus here)
zk+1 = zk − dk·atanh(2−ik)        ← atanh(2^−i) comes from a small ROM/LUT

      
x0, y0, z0 = start values; xN, yN, zN = final values (the result). Row k of the iteration table shows xk, yk, zk.

      
    
        
  • Rotation mode (cosh, sinh, exp): dk = sign(zk), drives z → 0. Start x0 = 1/K, y0 = 0, z0 = t → ends with xN = cosh t, yN = sinh t, zN ≈ 0. exp t = xN + yN.
    • 
        
  • Vectoring mode (atanh, ln, sqrt): dk = −sign(yk), drives y → 0. Ends with zN = z0 + atanh(y0/x0), xN = K·√(x0² − y0²), yN ≈ 0.
          
    ln w = 2·atanh((w−1)/(w+1)) → start x0 = w+1, y0 = w−1, z0 = 0, result 2·zN.
          
    √w = √((w+¼)² − (w−¼)²) → start x0 = w+¼, y0 = w−¼, z0 = 0, result xN · (1/K).
    • 
        
  • Shift starts at i=1 (atanh(2⁰)=∞), and i = 4, 13, 40… must be repeated (kₙ₊₁ = 3kₙ+1). Without repeats the remaining angles can't add up to cover the gap and it won't converge. In HW: the repeated stage is just an extra pipeline stage with the same shift.
    • 
        
  • Gain K = ∏√(1 − 2⁻²ⁱ) ≈ 0.8282 (it's <1, unlike circular's 1.647). Constant for fixed N → precompute.
    • 
        
  • Convergence range: |t| ≤ Σatanh(2⁻ⁱ) ≈ 1.118 for rotation; |y/x| ≤ tanh(1.118) ≈ 0.807 for vectoring (ln: w ∈ ~[0.107, 9.36], sqrt: w ∈ ~[0.027, 2.34]). Larger inputs need range reduction (e.g. exp t = 2ᵏ·exp(t − k·ln2)).
    • 
        
  • FPGA tips: >>> on signed = arithmetic shift (floor, as in the table). Pick W so the largest |x|, |y| fits: integer bits = W − F − 1 (sign). Each step gains ~1 bit of precision, so N ≈ F is a good start. Unrolled = N pipeline stages, 1 result/clock; iterative = 1 stage + counter + shift mux, N clocks/result.
